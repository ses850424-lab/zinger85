# 02. I/O 태그맵 (Modbus 레지스터 매핑) — 제안 주소 반영판

- 출처: `세척기_제어시스템_기획_20260826.md` 4항 (I/O 리스트 초안) + 2026-08-31 대화(리밋스위치·통신 아키텍처 확정) + 2026-08-31 병합(회전감지·서보 이동완료·고압펌프 이상신호 분리·파렛트회전 운전상태·오토사이클 시작/정지·운전모드전환 — 이전 답변 유효, 이번 문서에 병합)
- **아키텍처 확정(2026-08-31)**: 이 프로젝트의 HMI/미들웨어는 **PLC하고만 Modbus TCP로 통신**한다. PLC가 서보드라이버·인버터와 내부적으로 어떤 프로토콜(펄스열, 통신, 아날로그 등)을 쓰는지는 PLC업체의 구현 세부사항이며 이 프로젝트 범위 밖이다. 그래서 아래 표의 모든 신호는 원칙적으로 Modbus 주소를 가질 수 있다.
- **주소 배정 방식(2026-08-31 결정)**: PLC업체의 번호 지정을 기다리지 않고, 우리 쪽이 먼저 번호를 제안해서 PLC 발주 사양서에 포함한다. 번호 충돌이 있을 때만 PLC업체가 조정한다.
- **주소 변환 규칙(2026-08-31 확인)**: 아래 "제안 Modbus 주소"는 전통적 Modbus 오프셋 표기다. 실제 프로토콜 요청 주소(0-based)로 변환할 때: DI는 `label - 10001`, Coil은 `label - 1`, HR은 `label - 40001` 로 계산한다. `server/src/modbus/registerMap.js`는 이 변환된 0-based 주소를 `addr`로 저장하고, 전통 표기는 `label`로 같이 저장한다.
- 아래 "제안 Modbus 주소"는 초안이며, 최종 확정 시 이 문서를 갱신한 뒤 `server/src/modbus/registerMap.js`에 코드 상수로 반영한다. **이 문서가 단일 진실 소스(source of truth)이고, 코드는 이 문서를 그대로 반영한 결과물이어야 한다** — 코드를 먼저 고치고 문서를 나중에 맞추지 않는다.

## 갱신 규칙
- 새 신호가 필요해지면 이 표에 먼저 추가 → `registerMap.js`에 반영 → 어댑터 코드 작성 순서를 지킨다.
- 제안 주소가 PLC업체 협의로 바뀌면 이 표를 먼저 갱신하고 근거(예: "2026-XX-XX PLC업체 협의 결과")를 비고란에 남긴다.
