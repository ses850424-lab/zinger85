# 09. PLC 자체 제작 검토 (의사결정 자료)

- 작성일: 2026-09-03
- 배경: "PLC를 외주가 아니라 우리가 직접 만들 수 있는가"를 검토하는 단계. **기종 미정, 결정 전.**
- 목적: 결정에 필요한 판단 근거를 모은다. **결론을 내리는 문서가 아니다.**
- **이 문서에는 가격·납기·공수 수치가 없다.** 견적이 필요한 항목은 `(견적 필요)`로 두었다 (`CLAUDE.md` — 모르는 값은 임의로 채우지 않는다). 특정 모델명도 단정하지 않는다.
- 관련: `docs/08_PLC_발주사양서.md`(외주 발주용)는 **자체 제작으로 가더라도 그대로 구현 사양서가 된다.** 어느 쪽을 택하든 버려지지 않는다.

## 1. 판단 대상

| 안 | 내용 | PLC 로직 작성 주체 | 안전 책임 |
|---|---|---|---|
| **① 외주 유지 (현행)** | `docs/08`을 업체에 전달, 업체가 래더 작성 | 외주 업체 | 외주 업체 |
| **② 자체 제작** | PLC 하드웨어를 직접 선정·구성하고 로직도 직접 작성 | 발주처(+Claude가 코드 산출 지원) | **발주처로 이동** |

## 2. 이 설비가 PLC에 요구하는 최소 사양

`docs/02_IO_태그맵.md`의 57개 태그는 **전부가 배선되는 물리 I/O가 아니다.** 기종 선정에는 물리 점수만 필요하므로 아래와 같이 분류한다. (이 분류는 태그맵에서 파생시킨 것이며, 태그맵 자체를 바꾸는 게 아니다.)

### 2-1. 물리 입력 — 17점

| 신호 | 점수 |
|---|---|
| 안착확인 버튼 | 1 |
| 위치이동실린더 전진완료 / 후진완료 | 2 |
| 리프트실린더 상승완료 / 하강완료 | 2 |
| 노즐회전실린더 전진완료 / 후진완료 | 2 |
| 안전도어 닫힘·잠김 | 1 |
| 비상정지 (※ PLC 입력은 표시용, 차단은 하드와이어드 — §4) | 1 |
| 고압펌프 압력이상 / 유량이상 | 2 |
| 노즐 X축 최대·최소 리밋 | 2 |
| 노즐 Z축 최대·최소 리밋 | 2 |
| 노즐 X축 / Z축 회전감지 | 2 |
| **합계** | **17** |

### 2-2. 물리 출력 — 11점 (+ 펄스열 축 별도)

| 신호 | 점수 |
|---|---|
| 위치이동실린더 전진 / 후진 솔레노이드 | 2 |
| 리프트실린더 상승 / 하강 솔레노이드 | 2 |
| 노즐회전실린더 전진 / 후진 솔레노이드 | 2 |
| 도어 열림 / 닫힘 솔레노이드 | 2 |
| 실링 On/Off 솔레노이드 | 1 |
| 고압펌프 On/Off (릴레이/전자접촉기) | 1 |
| 완료램프·부저 | 1 |
| **합계** | **11** |
| **+ 노즐 X·Z축 펄스열 2축** | 축당 펄스+방향 = **4점 상당** |

### 2-3. 배선이 아닌 내부 비트 — 9점

기종 선정 시 **I/O 점수로 계산하면 안 되는** 항목이다. PLC 내부 메모리(M/D)로 처리된다.

- DI 영역 4개: `노즐X축_이동완료`, `노즐Z축_이동완료`, `파렛트회전_운전상태`, `경로점_저장확인`
- Coil 영역 5개: `오토사이클_시작`, `오토사이클_정지`, `운전모드_수동`, `경로점_저장`, `경로_저장완료`

> Holding Register 20점도 전부 데이터 레지스터이며 물리 배선이 아니다.
> (검증: 물리입력 17 + DI내부 4 = 21, 물리출력 11 + Coil내부 5 = 16, HR 20 — `registerMap.js`와 일치)

### 2-4. 필수 하드웨어 조건

| 조건 | 내용 | 왜 필요한가 |
|---|---|---|
| **트랜지스터 출력 필수** | 릴레이 출력형 PLC는 **사용 불가** | 노즐 X·Z축이 펄스열 제어(`docs/04` 확정). 릴레이 접점으로는 펄스를 낼 수 없음 |
| **위치결정 명령 2축 내장** | 펄스열 출력 + 위치결정 명령 | 서보 2축. 별도 위치결정 모듈을 쓰면 비용 증가 |
| **이더넷 + Modbus TCP 슬레이브** | 당사 미들웨어가 마스터로 접속 | 이게 없으면 HMI가 붙지 못함 — **선정 시 1순위 확인 항목** |
| **시리얼(RS-485) 포트** | 파렛트회전 인버터 통신용 | 프로토콜은 아직 미정 (`docs/04`) |
| **비휘발성(래치) 데이터 영역** | 기종별 경로 레시피 보관 | §2-5 |
| **I/O 점수 여유** | 입력 17 + 출력 15(펄스 포함) + 예비 | **32점형(입력16/출력16)은 입력이 1점 부족** — 64점급 또는 증설 구성 필요 |

### 2-5. 레시피 저장 용량 (선정 조건이 되는 이유)

FF 10종 + FR 10종 = **20 기종**의 노즐 경로를 PLC가 보관해야 하고(`docs/05_차량기종.md`), **정전 후에도 남아야 하므로 래치(비휘발성) 영역**이어야 한다.

```
필요 워드 수 = 20기종 × (기종당 경로점 수) × 2워드(X, Z)
```

기종당 경로점 수가 **아직 정해지지 않아 용량을 산정할 수 없다** (§7-①). 참고로 값을 넣어보면:

| 기종당 경로점 (가정) | 필요 워드 |
|---|---|
| 50점 | 2,000 워드 |
| 100점 | 4,000 워드 |
| 200점 | 8,000 워드 |

> 위 숫자는 **산식 예시일 뿐 확정값이 아니다.** 경로점 수가 정해져야 어느 기종의 래치 영역으로 충분한지 판단할 수 있다.

### 2-6. 이번 분류에서 드러난 설계 공백

**토크·전류 레지스터(`HR 40007`~`40012`)를 실제로 취득할 수 있는지 확인되지 않았다.**

- 서보(X·Z축)는 PLC와 **펄스열**로 연결된다(`docs/04` 확정). 펄스열은 PLC→드라이브 단방향 지령이므로, **드라이브의 토크·전류 값이 PLC로 자동으로 올라오지 않는다.** 읽으려면 드라이브의 아날로그 모니터 출력을 아날로그 입력으로 받거나, 별도 통신을 추가해야 한다.
- 파렛트 회전은 인버터와 "통신" 방식이라 취득 가능성이 있으나, 프로토콜이 미정이라 확정할 수 없다.

즉 **HMI 화면에 토크·전류를 표시하려면 하드웨어 구성이 추가로 필요할 수 있다.** 외주/자체 어느 쪽으로 가든 확인해야 하는 항목이다 (§7-②).

## 3. 기종 후보 비교

아래는 **구조적 속성 비교**이며, 세부 사양(내장 포트, 축수, 래치 용량)은 기종·형번마다 다르므로 **선정 시 해당 형번의 최신 데이터시트로 반드시 재확인해야 한다.** 이 표만 보고 발주하지 말 것.

| 항목 | 미쓰비시 (GX Works3) | LS일렉트릭 (XG5000) | 지멘스 (TIA Portal) |
|---|---|---|---|
| 대표 계열 | FX5U, iQ-R | XGB, XGK / XGI | S7-1200, S7-1500 |
| 접점 주소 표기 | `X0` / `Y0` / `D0` / `M0` | XGK: `P0000` / `M` / `D`<br>XGI: `%IX0.0` / `%QX0.0` | `I0.0` / `Q0.0` / `M` / `DB` |
| **ST 지원** | 지원 | **XGI 계열은 지원, XGK 계열은 래더/니모닉 중심** | SCL(=ST) 지원, 성숙도 높음 |
| 펄스열 위치결정 | 트랜지스터 출력형에 내장 | 트랜지스터 출력형에 내장 | DC/DC/DC 형에 PTO 내장 |
| Modbus TCP 슬레이브 | 기종별 지원 (형번 확인 필요) | 이더넷 내장형 또는 통신모듈 | 명령 블록으로 구현 |
| 국내 자료·A/S | 보급률 높음, 자료 많음 | 국산, 자료·기술지원 접근 용이 | 자료는 많으나 국내 현장 비중은 상대적으로 낮음 |
| **Claude 산출물 활용도** | ST 또는 렁 설계서 | **XGI면 ST, XGK면 렁 설계서** | **ST(SCL) 그대로 사용 — 가장 유리** |
| 가격·납기 | (견적 필요) | (견적 필요) | (견적 필요) |

**선정 시 판단 축 3가지**

1. **ST를 쓸 수 있는 기종인가** — 쓸 수 있으면 제가 만든 코드를 그대로 붙여넣을 수 있고, 아니면 제가 만든 렁 설계서를 보고 사람이 툴에 입력해야 한다. 작업량 차이가 크다.
2. **Modbus TCP 슬레이브가 되는가** — 안 되면 이 프로젝트의 HMI가 아예 붙지 않는다.
3. **현장에서 누가 유지보수하는가** — 설비 인수 후 고장 시 대응할 사람이 익숙한 브랜드인지가 실무에서는 위 두 가지보다 중요할 수 있다.

## 4. 자체 제작 시 안전 책임 (가장 중요)

### 4-1. 전제가 바뀐다

현행 원칙(`PROJECT_PLAN.md` §5, `CLAUDE.md`)은 이렇다.

> 안전 판단(도어 잠금 확인, 비상정지 등)은 **PLC/하드와이어드**의 몫이며, 이 소프트웨어(HMI/미들웨어)는 **상태를 표시만** 한다.

이 원칙은 "PLC는 외주"라는 전제 위에 서 있다. **PLC를 직접 만들면 그 안전 책임이 발주처로 이동한다.** 1000bar는 신체 절단·관통 손상이 가능한 압력이므로 이 이동은 가볍게 볼 사안이 아니다.

### 4-2. 다만 "자체 제작 = 안전까지 소프트웨어로" 는 아니다

실무에서 쓰는 분리선은 다음과 같다. 자체 제작을 하더라도 이 선은 그대로 유지하는 구성이 가능하다.

| 영역 | 구현 방식 | 담당 |
|---|---|---|
| **일반 시퀀스 로직** — 0~9단계 진행, 실린더 순서, 레시피 저장/재생, Modbus 슬레이브 매핑, HMI 지령 처리 | PLC 프로그램 (래더/ST) | 자체 제작 가능. **Claude가 코드 산출 지원** |
| **안전 관련 회로** — 비상정지, 도어인터록, 고압펌프 차단 | **하드와이어드 + 안전릴레이(또는 세이프티 PLC)**. 일반 PLC 프로그램에 의존하지 않음 | 전기 설계 영역. **소프트웨어로 대체하지 않는다** |

즉 자체 제작으로 가더라도 **안전회로는 여전히 소프트웨어 바깥에 하드웨어로 존재**해야 하고, 그 설계·시공은 전기 설계자의 몫이다.

### 4-3. 규격에 관하여

IEC 61508, ISO 13849-1, NFPA 79, KOSHA 지침 등의 적용 여부와 적합성 판단은 **기계안전 인증 컨설턴트의 영역**이며, 이 문서나 Claude가 대신하지 않는다. 자체 제작을 택할 경우 **외주 업체가 지고 있던 이 검토 부담도 함께 넘어온다**는 점을 비용에 포함해서 판단해야 한다 (`PROJECT_PLAN.md` §5와 동일한 원칙).

## 5. Claude가 산출할 수 있는 것 / 없는 것

| ✅ 가능 | ❌ 불가능 |
|---|---|
| **ST(구조화 텍스트) 소스** — 텍스트라 파일로 산출, 지원 기종이면 그대로 사용 | **제조사 프로젝트 파일 직접 생성** (`.gxw`, `.xgw`, `.ap17` 등 바이너리·독점 포맷) |
| **렁(rung) 단위 래더 설계서** — 접점/코일 구성을 표와 글로 기술, 사람이 툴에 입력 | **툴 조작** — GX Works3/XG5000/TIA Portal을 직접 띄워 그리기 |
| **I/O 할당표** — `docs/02` 태그를 기종별 주소(`X0`/`P0000`/`I0.0`)로 변환 | **실기 시운전** — 서보 게인 튜닝, 원점 조정, 세척력 확인 |
| **레시피 데이터 구조 설계** — D영역 배치, 20기종 경로 저장 방식 | **배선·판넬 제작** — 결선, 노이즈 대책, 접지 |
| **시퀀스 로직 검토** — 외주 납품물을 `docs/08` 기준으로 대조 (③안) | **안전회로 설계 승인** — 인증 컨설턴트 영역 |

**요약**: 논리(무엇을 어떤 조건에서 켜고 끄는가)는 산출 가능하고, 그것을 실제 장비에 심고 물리적으로 검증하는 일은 현장 몫이다.

## 6. 경로별 리스크 비교

| 축 | ① 외주 유지 | ② 자체 제작 |
|---|---|---|
| **안전 책임** | 업체가 부담 | **발주처로 이동** — 가장 큰 고려사항 |
| **초기 비용** | 업체 견적 (견적 필요) | PLC 하드웨어 + 인건비 (견적 필요) |
| **시운전 중 수정 속도** | 업체 일정에 의존 — 느릴 수 있음 | **즉시 수정 가능 — 가장 큰 장점** |
| **장기 유지보수** | 소스를 못 받으면 계속 업체에 의존 | 코드를 우리가 보유 |
| **문제 발생 시 책임 소재** | 명확 (계약) | 발주처 내부 |
| **학습·검증 부담** | 낮음 | 높음 — PLC 툴 숙련, 배선, 안전 검토 |
| **HMI 연동 리스크** | 업체가 Modbus 사양을 정확히 구현해야 함 (§7 회신 대기 12건) | **우리가 양쪽을 다 쥐므로 불일치 위험이 사라짐** |

**③ 병행안**은 위 둘의 중간이다. 계약상 책임은 업체에 두고, 우리가 `docs/08` 기준으로 로직을 써 봄으로써 (a) 납품물 검토 기준을 확보하고 (b) 시운전 중 문제를 빨리 짚을 수 있다. 다만 **인건비가 이중으로 든다.**

## 7. 결정 전 확인 필요 항목

`docs/04_확인필요사항.md`에 함께 등재한다. 직전(2026-09-03 발주사양서 정리)에 올린 ①~⑫와 중복되는 항목(인버터 프로토콜, 토크·전류 스케일 등)은 여기서 다시 쓰지 않고 그쪽을 참조한다.

| # | 항목 | 왜 결정에 필요한가 |
|---|---|---|
| ① | **기종당 경로점(웨이포인트) 상한** — 20기종 × N점 × 2워드 | N이 없으면 §2-5 래치 용량을 산정할 수 없고 → 기종 선정 불가 |
| ② | **토크·전류를 실제로 취득할 수 있는가** (§2-6) — 서보가 펄스열 연결이라 드라이브 상태가 자동으로 올라오지 않음. 아날로그 모니터 or 별도 통신 추가 필요 여부 | 필요하면 아날로그 입력 모듈이 추가되어 기종 선정과 비용이 바뀜 |
| ③ | **안전회로를 어디까지 하드와이어드로 구성할 것인가** — 안전릴레이 사용 여부, 세이프티 PLC 검토 여부 | 자체 제작의 실질 난이도와 비용을 좌우하는 항목 |
| ④ | **PLC 판넬 제작·배선 인력이 내부에 있는가** (또는 판넬만 외주 가능한가) | 로직만 우리가 하고 배선은 외주하는 분업이 가능한지 결정 |
| ⑤ | **설비 인수 후 유지보수 담당자가 익숙한 PLC 브랜드** | §3의 실무 판단축 3번 |
| ⑥ | **기종별 견적 및 납기** (미쓰비시 / LS / 지멘스) | ①~⑤가 정리된 뒤 견적 요청 |
| ⑦ | **외주 업체 계약에 소스 제공 조건이 포함되는가** (①안 선택 시) | 소스를 못 받으면 장기 유지보수가 업체에 종속됨 (§6) |
