- 작성일: 2026-09-03
- 목적: 외주 제작되는 PLC가 **래더 로직으로 구현해야 할 요구사항**과, 당사 HMI/미들웨어가 PLC에 기대하는 **Modbus 인터페이스**를 한 문서로 정리한다.
- **이 문서는 파생물이다.** 신호명·주소의 단일 진실 소스는 `docs/02_IO_태그맵.md`이며, 이 문서와 어긋나면 `docs/02`를 따른다. 시퀀스는 `docs/03_공정시퀀스.md`, 미확정 항목 추적은 `docs/04_확인필요사항.md`가 원본이다.

- 이 문서에서 `(제안)`, `(미정)`으로 표시된 항목은 당사가 임의로 확정한 값이 아니다 — §7의 회신 요청 항목과 1:1로 대응한다.

## 1. 범위와 역할 분담

근거: `PROJECT_PLAN.md` §1, `docs/01_설비개요.md`

| 영역 | 담당 |
|---|---|
| 기계설비 제작 | 발주처 직접 제작 |
| **PLC 시퀀스 래더 · 안전인터록 · 서보/인버터 드라이브 지령 · Modbus TCP 슬레이브** | **외주 PLC업체 (본 사양서의 대상)** |
| HMI 화면(산업용PC, HTML/JS) + 통신 미들웨어(Node.js, Modbus TCP 마스터) | 발주처 자체 개발 |

### 1-1. 당사 소프트웨어가 하지 않는 일 (중요)

1000bar 초고압수는 신체 절단·관통 손상이 가능한 등급이므로, 당사 HMI/미들웨어는 **안전 판단을 일절 수행하지 않는다**. 다음을 전제로 개발되어 있다.

- 비상정지, 도어 인터록, 고압펌프 이상 시 정지는 **PLC 및 하드와이어드 회로가 전담**한다.
- 당사가 읽는 `DI 10006`(안전도어), `DI 10007`(비상정지), `DI 10008/10013`(펌프 이상)은 **화면 표시용 미러 신호**일 뿐이며, 당사 코드는 이 값을 근거로 설비를 정지시키지 않는다.
- 따라서 **이 신호들이 표시용으로 나온다고 해서 안전 기능이 소프트웨어에 이중화되어 있다고 보지 말 것.** 안전 기능은 PLC/하드와이어드 쪽에만 존재해야 한다.

### 1-2. 연결 구조

```
[산업용PC: HMI 화면] --WebSocket--> [Node.js 미들웨어] --Modbus TCP--> [PLC] --> 서보드라이버 / 인버터 / 밸브
                                     (Modbus 마스터)                  (Modbus 슬레이브)
```

PLC 내부에서 서보드라이버·인버터와 어떤 방식(펄스열, 통신, 아날로그)으로 주고받는지는 **PLC업체 구현 범위**이며 본 사양서가 규정하지 않는다. 당사는 PLC의 Modbus 레지스터만 본다.

## 2. 통신 사양

| 항목 | 값 | 상태 |
|---|---|---|
| 프로토콜 | Modbus TCP | 확정 |
| 역할 | **PLC = 슬레이브(서버)**, 당사 미들웨어 = 마스터(클라이언트) | 확정 |
| Unit ID (Slave ID) | 1 | (제안) — §7 회신 항목 |
| PLC IP 주소 | (미정) | §7 회신 항목 |
| TCP 포트 | 502 | (제안) |
| 폴링 주기 | (미정) — 당사 개발 기본값 300ms | §7 회신 항목 (PLC 허용 부하 기준 회신 요망) |
| 동시 접속 마스터 수 | 1 (미들웨어 1개) | 확정 |

### 2-1. 사용 함수코드

당사 미들웨어(`server/src/modbus/client.js`)가 실제로 사용하는 것은 아래 5개뿐이다. 이 5개를 지원하면 충분하다.

| 함수코드 | 용도 |
|---|---|
| FC01 (Read Coils) | 출력 비트 현재 상태 확인 |
| FC02 (Read Discrete Inputs) | 센서·상태 비트 읽기 |
| FC03 (Read Holding Registers) | 워드값 읽기 |
| FC05 (Write Single Coil) | 출력 비트 쓰기 |
| FC06 (Write Single Register) | 워드값 쓰기 |

- 다중 쓰기(FC15/FC16)는 사용하지 않는다. 여러 레지스터를 쓸 때도 **FC06을 연속 호출**한다 (§6 경로 전달 시 주의).

### 2-2. 주소 표기 변환 규칙

§3의 주소는 전통적 Modbus 오프셋 표기다. 실제 프로토콜 요청 주소(0-based)는 다음과 같이 계산된다.

| 영역 | 표기 | 프로토콜 주소 |
|---|---|---|
| Discrete Input | `10001` ~ | `표기 - 10001` → 0 ~ |
| Coil | `00001` ~ | `표기 - 1` → 0 ~ |
| Holding Register | `40001` ~ | `표기 - 40001` → 0 ~ |

각 영역은 **서로 다른 주소공간**이며 각각 0부터 시작한다.

## 4. 시퀀스 요구사항 (래더 구현 대상)

근거: `docs/03_공정시퀀스.md`. 아래 표에서 **(제안)** 표시는 원본 시퀀스 문서에 명시되지 않아 당사가 태그 구성에서 추정한 것이므로, PLC업체가 확정해 회신해 주기 바란다.

### 4-1. PLC 필수 구현 사항

**현재 진행 단계를 항상 `HR 40002`에 0~9 정수로 발행할 것.** 당사 HMI는 이 값 하나만 읽어 화면에 단계를 표시하며(`server/src/sequence/stateMachine.js`), 자체적으로 단계를 계산하지 않는다. 이 레지스터가 갱신되지 않으면 HMI의 단계 표시가 전혀 동작하지 않는다.

### 4-2. 단계별 요구사항

| 단계 | 진입 조건 | PLC 동작 | 완료(다음 단계 전이) 조건 |
|---|---|---|---|
| **0. 대기** | 전원 투입, 복전, 사이클 종료, `Coil 00008` 정지 지령 | 전 출력 정지, `HR 40002 = 0` | `DI 10001` 안착확인 버튼 ON |
| **1. 파렛트 로딩** | 안착확인 버튼 ON | `HR 40002 = 1` | (제안) `Coil 00007` 오토사이클 시작 ON — **§7-2 ①: 자동사이클 시작 트리거가 안착확인 버튼인지 HMI 시작 지령인지 확정 요망** |
| **2. 위치이동** | 1단계 완료 | `Coil 00001` 전진 출력, `HR 40002 = 2` | `DI 10002` 전진완료 ON |
| **3. 리프트 업** | 2단계 완료 | `Coil 00003` 상승 출력, `HR 40002 = 3` | `DI 10004` 상승완료 ON |
| **4. 안전 확인** | 3단계 완료 | `Coil 00013` 도어 닫힘 → `DI 10006` 확인 → `Coil 00014` 실링 ON, `HR 40002 = 4` | `DI 10006` 닫힘·잠김 ON. **실링 완료 확인 센서는 존재하지 않음** — 실링 완료 판정 방법(타이머 등)은 PLC업체 설계 (§7-2 ②) |
| **5. 세척** | 4단계 완료 **및 도어 잠김 유지** | `HR 40001` 속도로 파렛트 회전, 선택 기종의 저장된 경로(§6)를 따라 노즐 X/Z 위치제어, `Coil 00005` 고압펌프 ON, `HR 40002 = 5` | 설정 세척시간 경과 또는 궤적 종료. **세척시간을 HMI에서 조정할 레지스터가 태그맵에 없음 — §7-2 ③** |
| **6. 세척 종료** | 5단계 완료 | `Coil 00005` 펌프 OFF → 파렛트 회전 정지 → 노즐 원점 복귀 (**순서 준수**), `HR 40002 = 6` | 노즐 원점 복귀 완료. **원점복귀 지령/완료 태그가 태그맵에 없음 — PLC 내부 처리로 가정 (§7-2 ④)** |
| **7. 리프트 다운** | 6단계 완료 | `Coil 00004` 하강 출력, `HR 40002 = 7` | `DI 10005` 하강완료 ON |
| **8. 위치 복귀** | 7단계 완료 | `Coil 00002` 후진 출력, `HR 40002 = 8` | `DI 10003` 후진완료 ON |
| **9. 완료** | 8단계 완료 | `Coil 00006` 완료램프/부저 ON, `HR 40002 = 9` | (제안) 반출 후 0단계 복귀. **램프/부저 해제 조건과 도어 열림(`Coil 00012`) 지령 주체가 미정 — §7-2 ⑤** |

### 4-3. 전 구간 공통 (안전)

- **비상정지 시**: 즉시 전체 정지 (PLC/하드와이어드).
- **도어 열림 감지 시**: 고압펌프·노즐 이송·파렛트 회전을 즉시 정지.
- **고압펌프 압력이상(`DI 10008`) 또는 유량이상(`DI 10013`) 감지 시**: PLC가 운전 정지.

위 3개 조건은 당사 HMI에서 **표시만** 하며, 정지 동작 자체는 전적으로 PLC/하드와이어드가 수행한다.

### 4-4. 수동 모드

- `Coil 00009`가 1이면 HMI가 수동화면에 있다는 뜻이다. 이는 **참고 신호**이며, 수동 조작을 허용할지 여부는 PLC가 판단한다.
- 수동 모드에서 당사 HMI는 실린더 전/후진, 노즐 X/Z 개별 이동(`HR 40003/40005`), 펌프 On/Off, 파렛트 회전속도, 도어 개폐를 **개별 코일/레지스터에 직접 쓴다.**
- 따라서 **자동 사이클 진행 중 수동 지령이 들어와도 위험 동작이 일어나지 않도록 PLC 래더에서 모드 인터록을 구현해야 한다.** 당사 코드는 이 판단을 하지 않는다.

## 5. 안전 요구사항 (당사가 전제하고 있는 사항)

당사 HMI/미들웨어는 아래가 PLC/하드와이어드에서 보장된다는 전제로 설계되어 있다. 보장되지 않는 항목이 있으면 **설계 전에 회신 바란다.**

| # | 요구사항 | 이유 |
|---|---|---|
| 1 | 비상정지·도어인터록은 하드와이어드 및 PLC가 전담하고, 통신(Modbus) 경로에 의존하지 않을 것 | 통신 지연·두절 시에도 안전 기능이 살아있어야 함 |
| 2 | 비상정지·도어인터록 계열 입력은 **NC(normally closed) 접점** 사용을 권장 | 신호선 단선 시 "정지 신호 입력"으로 해석되어야 함(fail-safe). 채택한 접점 방식을 회신 바람 |
| 3 | **통신 두절 시 마지막 지령을 유지(hold)하지 말고 안전한 정지 상태로 폴백할 것** | 당사 미들웨어는 연결이 끊기면 재접속을 시도할 뿐(backoff 1초→최대 30초), 정지 지령을 보낼 수 없음. 특히 `Coil 00005` 고압펌프가 ON인 채로 통신이 끊기는 경우가 위험 |
| 4 | **복전(정전 후 재기동) 시 이전 사이클을 자동으로 이어가지 말 것.** 0단계(대기)로 복귀하고 `HR 40002 = 0` 발행 | 무인 재기동 방지 |
| 5 | 리밋스위치·푸시버튼 등 기계식 접점의 **디바운싱은 PLC 책임** | 당사는 수신한 비트를 그대로 화면에 표시할 뿐, 채터링 필터를 두지 않음 |
| 6 | 상반된 방향 코일 쌍(§3-2)의 동시 ON을 래더에서 배타 처리할 것 | 당사 미들웨어가 반대쪽 코일을 0으로 내리지 않음 |
| 7 | 어떤 경로로도 `Coil 00009`(수동모드) 등 HMI 지령이 도어인터록·비상정지를 우회하지 못하게 할 것 | 당사 지령은 신뢰 경계 밖의 입력으로 취급되어야 함 |

**규격 적합성에 관하여**: IEC 61508, ISO 13849-1, NFPA 79, KOSHA 지침 등의 적용·적합성 판단은 본 문서의 범위가 아니며, PLC업체 또는 기계안전 인증 컨설턴트가 별도로 확인해야 한다. 발주처는 본 사양서로 특정 규격 준수를 주장하지 않는다 (`PROJECT_PLAN.md` §5).

## 6. 기종별 노즐 경로 전달 핸드셰이크

근거: `docs/05_차량기종.md`, 구현: `server/src/io/motor/vehicleModelRecipe.js`

### 6-1. 배경

세척 대상 미션은 FF(전륜) 10종 + FR(후륜) 10종 = **총 20 기종**이며, 기종마다 노즐이 지나갈 경로(X/Z 좌표점 목록)가 다르다. 경로는 시운전 중 HMI에서 조그 이동으로 티칭해 만들고, 완성되면 **PLC로 전달해 PLC의 레시피 메모리에 저장**한다. 세척 사이클(§4 5단계)에서는 **PLC가 저장된 경로를 따라 위치제어를 수행**한다 — 당사는 경로를 전달만 하고 실행하지 않는다.

### 6-2. 전송 절차 (당사 미들웨어가 수행하는 순서)

```
1) HR 40015 ← 모델 카테고리 (0=FF, 1=FR)      [FC06]
2) HR 40016 ← 모델 번호 (1~10)                 [FC06]

   각 경로점마다 반복:
3)   HR 40017 ← 경로점 인덱스 (0부터 증가)     [FC06]
4)   HR 40018 ← 경로점 X (0.1mm 단위 정수)     [FC06]
5)   HR 40019 ← 경로점 Z (0.1mm 단위 정수)     [FC06]
6)   Coil 00015 ← 1  (경로점 저장 요청)        [FC05]
7)   → PLC가 40017/40018/40019 값을 해당 모델 레시피에 기록
8)   → PLC가 DI 10021 (경로점 저장확인) 을 ON
9)   당사가 ack 확인 후 Coil 00015 ← 0         [FC05]
10)  → PLC는 이 시점에 DI 10021 을 OFF 로 복귀시킬 것 (제안)

   전체 점 전송 후:
11) Coil 00016 ← 1, 곧이어 0 (펄스)  → PLC가 레시피 확정
12) HR 40020 (경로 저장개수) 로 당사가 전송 결과를 검증
```

### 6-3. PLC 구현 시 주의

- **레지스터는 FC06으로 1개씩 순차 기록된다.** 인덱스/X/Z가 원자적으로 동시에 바뀌지 않으므로, **`Coil 00015`가 1이 되는 시점의 값만 유효한 것으로 취급**해야 한다. 그 전의 중간 상태를 읽어 기록하면 안 된다.
- **ack 타임아웃**: 당사는 `Coil 00015`를 1로 쓴 뒤 **100ms 간격으로 폴링하며 최대 5초** 안에 `DI 10021`이 ON 되지 않으면 전송 실패로 처리하고 중단한다.
- **ack 클리어 주체 (미정, §7-2 ⑥)**: 당사는 ack 확인 후 `Coil 00015`를 0으로 내린다. 그에 맞춰 PLC가 `DI 10021`을 OFF로 되돌려 줘야 다음 점에서 이전 ack를 오인하지 않는다. 이 규칙을 확정해 회신 바람.
- `HR 40020`은 해당 모델에 지금까지 기록 확인된 점 개수를 반영해야 한다 (전송 진행률·검증용).

## 7. 회신 요청 항목

### 7-1. 기존 미확정 항목 (`docs/04_확인필요사항.md`)

| # | 항목 |
|---|---|
| 1 | 인버터-PLC 간 세부 통신 프로토콜 (Modbus RTU 등) — 당사 레지스터 설계에는 영향 없으나 시운전 시 참고 필요 |
| 2 | 노즐 X·Z축 원점/리미트 센서 구성 — 축당 최대리밋 1 + 최소리밋 1 + 회전감지 1 = 3점으로 반영했으나 최종 확인 요망 |

### 7-2. 본 사양서 작성 중 새로 도출된 항목

| # | 항목 | 왜 필요한가 |
|---|---|---|
| ① | **자동 사이클 시작 트리거** — `DI 10001` 안착확인 버튼인가, `Coil 00007` HMI 시작 지령인가, 둘 다 필요(AND)인가 | `docs/03` 1단계에 정의 없음. HMI 시작 버튼 동작이 여기에 달려 있음 |
| ② | **실링 완료 판정 방법** — 별도 완료센서가 없음 (타이머? 압력스위치 추가?) | 4단계 전이 조건이 정해지지 않음 |
| ③ | **세척시간 설정 레지스터 필요 여부** — 현재 태그맵에 없음. 초기값 10분은 시운전 후 조정 대상인데, HMI에서 조정하려면 HR 태그를 신설해야 함 | 필요하다고 회신되면 `docs/02`에 태그를 추가해야 함 |
| ④ | **노즐 원점복귀 지령/완료 태그 필요 여부** — 현재 태그맵에 없어 6단계 원점복귀를 PLC 내부 처리로 가정 | HMI에서 수동 원점복귀가 필요하면 태그 신설 필요 |
| ⑤ | **완료램프/부저(`Coil 00006`) 해제 조건**과 **도어 열림(`Coil 00012`) 지령 주체** (PLC 자동 / HMI 수동 / 작업자 버튼) | 9단계 종료 처리가 정해지지 않음 |
| ⑥ | **경로점 ack(`DI 10021`) 클리어 주체와 타임아웃** (§6-3) | 당사는 5초 타임아웃 가정 중 |
| ⑦ | **`Coil 00007/00008` 오토사이클 시작·정지가 펄스(엣지)인가 레벨 유지인가** — 당사 미들웨어는 현재 1을 쓰기만 하고 0으로 내리지 않음 | PLC가 엣지 검출로 처리하면 두 번째 사이클이 시작되지 않음. 확정에 따라 당사 코드를 조정할 예정 |
| ⑧ | **상반 코일 쌍의 배타 처리 방식** (§3-2, §5-6) 및 **실린더가 더블솔레노이드인지 싱글솔레노이드인지** | 싱글이면 코일 2개를 1개로 통합하고 태그맵을 줄여야 함 |
| ⑨ | **통신 두절 감지용 워치독 레지스터 필요 여부** — 현재 태그맵에 없음. 필요하면 지금 태그를 신설해야 함 (예: 당사가 주기적으로 카운트를 올려 쓰고, PLC가 일정 시간 갱신이 없으면 안전정지) | §5-3을 PLC가 자체적으로 보장하지 못하는 경우 필수 |
| ⑩ | **토크·전류 레지스터(`HR 40007`~`40012`) 실제 스케일** — `0.01N·m`, `0.01A`는 당사 제안값 | HMI 표시값이 틀어짐 |
| ⑪ | **위치 레지스터 스케일** — `0.1mm/count` 제안값 확정 요망. 음수 좌표 사용 여부(부호 있는 16bit인지)도 함께 | 좌표 변환 로직에 직접 영향 |
| ⑫ | **PLC IP 주소, TCP 포트, Unit ID, 허용 폴링 주기** | 접속 설정값 |

### 7-3. 주소 충돌 시 회신 양식

제안 주소가 업체 기존 체계와 충돌하면 아래 형식으로 회신해 주면 당사가 `docs/02_IO_태그맵.md` → `server/src/modbus/registerMap.js` 순서로 반영한다. **신호명은 유지하고 주소만 바꾸는 형태를 선호한다.**

| 신호명 | 당사 제안 주소 | 업체 지정 주소 | 사유 |
|---|---|---|---|
| (예) 리프트실린더 상승 | Coil 00003 | Coil 00021 | 기존 설비와 주소 대역 충돌 |
